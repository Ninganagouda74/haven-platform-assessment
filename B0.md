# B0 — The `count` trap

What does `terraform plan` show when a middle landlord account is removed from the list? Why is
that dangerous here? What's the fix?

What terraform plan shows:
    Terraform gives each bucket a number based on its place in the list:0 1 2 3 it doesnt remeber which landloard a bucket belongs to only the number

    our list is la-001, la-002, la-003, la-004 when i removed la-002 and ran terraform plan -refresh=false everyone after it moved up one place

    1.bucket 0 (la-001): no changes
    2.bucket 1 was la-002: now that spot belongs to la-003 so the bucket name changes and terraform plans to destrory and recreate it
    3.bucket 2 was la-003: now it belongs to la-004 so same thing 
    4.bucket 3 (la-004): has no spot any more so it gets destroyed


Why its dangerous:
    1. la-003 and la-004 did nothing wrong but their buckets get deleted and recreated their media can be lost or the apply can stop halfway
    2. bucket names are unqiue across all of aws bucket 1 needs the name haven-media-la-003 while that bucket still exists so it can fail
    3. the plan looks like remove one landlord so its easy to approve without noticing


The Fix:
    1. use for_each with the landlord ID istead of count so each bucket is tied to its landloard and not it to a posotion
    2. add moved blocks so the exisitng bucktes are renamed in terraforms state without being destroyed 
    3. add prevent_destroy=true and keep force_destroy= false so a bucket cant be deleted by mistake
